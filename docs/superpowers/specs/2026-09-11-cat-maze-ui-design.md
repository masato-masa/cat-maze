# ねこめいろ プレイ画面 UI 刷新 設計

2026-09-11

## なぜ直すのか

プレイ画面で**視覚的な強さの順序が、意味の重要度と逆さま**になっている。

| 画面での目立ち方 | 要素 | 実際の重要度 |
|---|---|---|
| 1番強い | 木目テクスチャ（濃い茶／明るい茶の市松） | ゼロ。意味を持たない |
| 2番目 | 黒い穴、ステッカー調の家と猫 | 中 |
| 一番弱い | 道 | 最重要。これがパズルそのもの |

W1-1 の盤は 4x4 で、1 マスが穴、残り 15 枚がタイル。そのうち道を持つのは
`E` / `EW` / `GOAL:W` の 3 枚だけで、残り 12 枚は `X`（`conn` が 0）＝模様だけの木片。
プレイヤーが見るべき道の形が、無意味な木目のノイズに埋もれている。

「安っぽい」の正体は素材の絵の巧拙ではなく、**素材を使う場所を間違えている**こと。
よって素材を描き直すのではなく、**盤面から画像を外してコードで描く**。

ホーム画面とステージ選択画面はすでに落ち着いているので触らない。

## 参考にする値

にゃんどく（`C:\claude\test`）の `src/ui/styles.css` から実測した値をそのまま使う。
目分量で似せた数字は入れない（`C:\claude\CLAUDE.md` の最重要ルール）。

にゃんどくの猫画像は第三者の素材ではなく自作なので、流用してよい。

### 構造の数値

| 項目 | 現状 | 新 |
|---|---|---|
| 盤の幅 | `min(92vw, 460px)` | `min(92vw, 452px)` |
| 盤の高さ | `46vh` で固定 | 残り全部（`flex: 1`） |
| 盤の背景 | `--bg-soft`（地とほぼ同色） | `--surface`（白いカード） |
| 盤の角丸 | `calc(var(--radius) + 4px)` = 18px | 16px |
| 盤の内側余白 | `gap/2` = 2px | 16px |
| セル間 | 4px | 6px |
| セルの角丸 | 12px | 8px |
| 影 | `0 2px 0 rgba(61,50,38,.12)` | `0 1px 2px 0 rgb(0 0 0 / .05)` |
| イージング | `ease-out` | `cubic-bezier(.4, 0, .2, 1)` |
| 色の遷移 | 160ms | 180ms |

にゃんどくで効いているのは**白いカードの中に地の色のセルを置く二層構造**。
ねこめいろは盤の背景が地と近く輪郭が曖昧なので、ここを白カードにする。

### 色

色相はねこめいろの暖色（クリーム＋オレンジ）を維持する。棚に 5 本並べたとき
にゃんどくと見分けがつかなくなるのを避けるため。`base.css` のトークンのうち
変えるのは次の 3 つだけ。

| トークン | 現状 | 新 | 理由 |
|---|---|---|---|
| `--tile-fixed` | `#d9c6ab` | `#e8dcc8` | 固定タイルが盤面で 2 番目に目立つ必要はない |
| `--road-outline` | `#47230f` | `#8a5230` | ほぼ黒で硬い。地に馴染ませる |
| `--hole` | `#ad9678` | 使わない（盤の地をそのまま見せる） | タイルが無いのだから下地が見えるのが自然 |

さらに `--road-lit` を新設する（`--road` の明度 +12% ＝ `#e5a468`）。
到達可能なマスの道をこの色にする。

ダークモードの対応するトークンも同じ考え方で引き直す。

## 1. 盤面をコードで描く

### 削除する素材

`src/assets/img/` から 5 枚を削除する。

- `tile.png` / `tile_fixed.png` — 木目テクスチャ。意味を持たないのに一番目立っていた
- `hole.png` — 黒い穴。異物感が強い
- `house.png` / `fish.png` — ステッカー調で盤面のトーンと噛み合わない

`cat.png` は削除し、にゃんどくの 4 表情に差し替える（後述）。
結果として `src/assets/img/` は空になり、`src/assets/cats/` だけが残る。

### タイル

| 種別 | 表現 |
|---|---|
| 可動 | `--tile`（`#fff6e8`）の単色。角丸 8px |
| 固定 | `--tile-fixed`（`#e8dcc8`）の単色。同じ角丸。**それ以外の差をつけない** |

固定タイルは「動かない」ことさえ伝わればよい。現状の濃い茶の木目は、
盤面の半分近くを占めて市松のノイズを作っていた。

### 道

`tile-svg.ts` の `roadSvg()` の構造は変えない。中心から開いている方角へ `<line>` を
引き、中心にハブの `<circle>` を置き、太い縁取り色の層の上に細い道の色の層を重ねる。
この方式は「どんな形でも太さ・縁取りが 1px も違わない」という要件を満たす唯一の解として
すでに結論が出ている（`[[cat-maze-image-asset-pipeline]]` 参照）。

変えるのは太さと色だけ。

| | 現状 | 新 |
|---|---|---|
| 縁取りの線幅 | 30 | 40 |
| 道の線幅 | 24 | 32 |
| ハブの半径（縁取り／道） | 15 / 12 | 20 / 16 |

100 座標系での値。これで道が「タイルの模様」から「タイルを貫く通路」になる。

### 穴

`hole.png` と `--hole` の背景色をやめ、**盤の地の色（白いカード）をそのまま見せる**。
`inset 0 2px 4px rgb(0 0 0 / .10)` の内側の影だけを落として、穴が開いていることを示す。

### 家（ゴール）

画像をやめ、**道と同じペンで描いた単色シルエット**にする。`tile-svg.ts` に
`houseSvg()` を追加し、`--road-outline` で輪郭、`--goal` で塗る 2 トーンの SVG を
タイル中心に 52% の大きさで置く。道と同じ線幅・同じ色系統で描かれることで盤面に溶ける。

### 魚

同じく単色 SVG。`fishSvg()` を追加し `--fish` で塗る。大きさは 36%（現状と同じ）。

### 到達可能の表示

現状の `tile-reach-glow`（黄色い放射グラデが 1500ms で明滅）は強すぎて、
盤全体が点滅して見える。これを削除し、**そのマスの道だけを明るくする**。

```
.tile.reachable .tile-road-fill line,
.tile.reachable .tile-road-fill circle { stroke: var(--road-lit); fill: var(--road-lit); }
```

`--road-lit` は `--road` を明度 +12% したもの。明滅させない。
猫が歩ける範囲が「明るい道として一本に繋がって見える」ほうが、パズルの情報として正しい。

## 2. 猫とアニメーション

### 素材

にゃんどくの `public/cats/{normal,blink,happy,sad}.png`（各 256px、約 25KB）を
`src/assets/cats/` にコピーする。ねこめいろは Vite の `import` で URL を得る方式なので、
`public/` ではなく `src/assets/` に置いてハッシュ付き URL にする。

### 実装

にゃんどくの `src/ui/Cat.tsx` のロジックを vanilla TS のクラス `CatSprite`
（`src/ui/cat-sprite.ts`）に移植する。React に依存している部分は state ではなく
`img.src` の直接差し替えに置き換える。移植する要点は 2 つ。

- **4 枚を先読みする。** まばたきの瞬間に取りに行くと、そこで猫が一瞬消える
- **まばたきの間隔をばらつかせる。** 等間隔だと生き物ではなく点滅に見える

### 動きの一覧

| きっかけ | 動き | 値 |
|---|---|---|
| 待機 | まばたき | 初回 900ms + `(seed % 5) * 700ms`、以降 2600〜6800ms のランダム。閉じている時間 130ms |
| 待機 | 呼吸 | `transform: scale(1)` → `scale(1.035)`、3.6s、`ease-in-out`、無限 |
| 歩行 | 向き | 進行方向が西なら `scaleX(-1)` |
| 歩行 | 跳ね | 1 マスごとに `translateY(-6%)` の山を 1 つ |
| 魚を取る | 表情 | `happy` を 700ms |
| 行けないマスをタップ | 表情と揺れ | `sad` を 400ms ＋ 左右に ±4% の揺れ 2 往復 |
| クリア | 表情とジャンプ | `happy` のまま既存の `cat-hop`（520ms × 2 回） |

呼吸の値はにゃんどくの `cat-breathe` の実測値。

「行けないマスをタップ」は**現状まったく無反応**で、壊れているように見える。
ここに反応を返すのが今回のアニメーションで一番効く。

### 歩行の跳ねの実装

猫の移動はすでに Web Animations API で経路全体を 1 本のキーフレームとして
再生している（`board-view.ts` の `walkCatThrough`）。区間ごとに transition を
打ち直すと境界で減速・再加速して止まって見えるためで、この方式は維持する。

跳ねは、既存の `transform: translate(...)` のキーフレームに `translateY` の
山を足す形で同じアニメーションに混ぜる。マスの中間点に `-6%` の中間キーフレームを
差し込むので、キーフレーム数は `path.length * 2 - 1` になる。

`prefers-reduced-motion: reduce` のときは呼吸・跳ね・揺れをすべて止める
（`base.css` に既存の仕組みがある）。表情の切り替えは残す。

## 3. 操作の手応え

### 直す 5 点

| # | 直すもの | 効果 |
|---|---|---|
| 1 | `el.innerHTML = tileSvg(tile)` を毎手・全タイルで実行している | 1 手ごとの `<img>` 再生成が消える。**体感の主因** |
| 2 | タップが合成 `click` 待ちになっている | 指を離した直後に反応する |
| 3 | `requestAnimationFrame` で全タイルの位置適用を 1 フレーム遅らせている | 遅れを最小化 |
| 4 | 歩行中のタップを捨てている（`walking` フラグ） | 連続タップが効くようになる |
| 5 | `reachableSet(s)` を `onCellClick` と `draw` で 2 回計算している | 無駄計算の除去 |

### 1. タイルの差分更新

`tile-svg.ts` を 2 つの関数に割る。

- `createTileEl(tile): HTMLElement` — 初回だけ呼ぶ。DOM を組み立てる
- `updateTileEl(el, tile): void` — 以降はこちら。変わったものだけ触る

`el.dataset.conn` / `el.dataset.kind` / `el.dataset.fish` に前回の値を持たせ、
一致していれば何もしない。道の `<svg>` は `conn` が変わったときだけ `innerHTML` を
書き換える。魚は `hidden` の付け外し。家は初回のみ。

タイルの見た目が変わるのは実質「魚を取ったとき」だけなので、
ほとんどの手で DOM の書き換えはゼロになる。

### 2. `pointerdown` で受ける

`input.ts` の `touchstart` / `touchend` / `click` の 3 本立てをやめ、
Pointer Events に一本化する。

- `pointerdown` — 始点と始点のマスを記録
- `pointerup` — 移動量が 7px 以下ならタップ（歩行）、超えていればスワイプ（タイルを押す）

閾値は現状の 10px から 7px に下げる（`CLAUDE.md` の「ドラッグとタップを閾値で分ける
（7px 程度）」に合わせる）。`board-view.ts` の `root.addEventListener('click', ...)` と
`swallowNextClick` の仕組みは不要になるので削除する。

キーボード入力（`keydown`）は現状のまま変えない。

### 3. 位置適用の限定

`render()` が `requestAnimationFrame` で全タイルに `place()` をかけている。
位置が前回と変わったタイルだけを `moved` に入れ、変わっていないタイルは
`rAF` を待たずに即座に属性を更新する。

### 4. 先行入力

`walking` フラグで入力を捨てるのをやめ、**先行入力を 1 つだけ覚える**。
歩行アニメーションが終わった時点で、覚えている入力があれば即座に実行する。
2 つ以上は覚えない（覚えると意図しない移動が連鎖する）。

`undo` / `restart` / `back` は先行入力ではなく即座に実行し、覚えている入力を捨てる。

### 5. 効果音と触覚

ねこめいろには効果音が一切ない。`CLAUDE.md` の既定値どおり
**WebAudio で合成する**（音声ファイルを持たない。読み込みゼロ、容量ゼロ、遅延ゼロ）。

`src/ui/sfx.ts` を新設する。にゃんどくの `src/core/sfx.ts` に同じ目的の実装が
あるので、その作法をそのまま持ってくる。

- `AudioContext` は遅延生成し、`suspended` なら `resume()` する
- master gain 0.5 → `lowpass` 4200Hz → destination
- 音は `tone({ freq, duration, type, gain, delay, slideTo })` 1 本で作る。
  倍音の少ない波形を軽いローパスに通し、減衰を指数カーブにして耳に刺さらないようにする

| きっかけ | 音 |
|---|---|
| 歩く（1 マスごと） | 短く柔らかいクリック。周波数は低め、40ms |
| タイルが動く | 木をすべらせる音。ノイズ + ローパス、120ms |
| 行けないマスをタップ | 低く短い「こつん」。30ms |
| 魚を取る | 上がる 2 音。明るい |
| クリア | 上がる 4 音のアルペジオ |

音量は控えめ（ピーク 0.25 程度）。ヘッダに消音トグルを置き、
`localStorage` に保存する（にゃんどくと同じ）。

触覚は `navigator.vibrate` で返す。タイルが動いたとき 10ms、
行けないとき 20ms、クリア時 `[40, 60, 40]`。対応していない環境では何も起きない。

### 音とゲーム状態の繋ぎ方

`GameSession` は純粋な状態遷移で、イベントを発火しない。この設計は変えない。
UI 側で**前後の状態を比べて**鳴らす。

| 音 | 判定 |
|---|---|
| タイルが動く | `moves` が増えた |
| 魚を取る | `fishTaken` が増えた |
| クリア | `cleared` が false から true になった |
| 行けない | `walk()` / `slide()` が同一オブジェクトを返した（変化なし） |

歩行音だけは 1 マスごとに鳴らす必要があるので、`walkCatThrough` の
経路の長さと `WALK_STEP_MS` から `setTimeout` で刻む。

## 4. プレイ画面のレイアウト

### 現状の問題

- 盤が `46vh` に制限されていて、画面上部に大きな死に空白ができている
- ヘッダの 3 要素（戻る／ステージ名／手数）が左右非対称に散っている
- 操作説明が常時 2 行出ていて、画面が説明くさい
- 「さかな n/m」が盤の下に独立した行を占めて、さらに空白を作っている
- フッタの横長ボタン 3 つが画面幅いっぱいに広がって重い

### 新しい構成

```
┌─────────────────────────────┐
│ ‹   うらにわ W1-1          12 │  ヘッダ（3分割グリッド）
│     はじめの いっぽ  🐟2/3  さいたん 8 │
├─────────────────────────────┤
│                             │
│    ┌───────────────────┐    │
│    │                   │    │
│    │   盤（白カード）    │    │  flex: 1 の中央
│    │                   │    │
│    └───────────────────┘    │
│                             │
├─────────────────────────────┤
│      ◯      ◯      ◯       │  丸アイコン 3 つ
└─────────────────────────────┘
```

| 要素 | 仕様 |
|---|---|
| ヘッダ | `grid-template-columns: 44px 1fr auto`。現状の構造を維持 |
| さかな | 独立した行をやめ、ヘッダ右の手数の下に小さなピルとして統合 |
| 盤 | `flex: 1` の中で中央寄せ。`--avail-h` の制限を外す |
| 操作説明 | 常時表示をやめる。**そのステージで最初の 1 手を打つまで**盤の上に 1 行だけ出し、打ったら消す |
| フッタ | 丸アイコンボタン 3 つ（もどす／やりなおし／ヒント）を `gap: 24px` で中央に |

### 丸アイコンボタン

にゃんどくの `.tool` の実測値をそのまま使う。

```
60x60 / padding 10px / border-radius 999px / background #fff
box-shadow: 0 1px 2px 0 rgb(0 0 0 / .05)
:active:not(:disabled) { transform: scale(0.9) }
:disabled { opacity: 0.35 }
中の svg は 40x40
```

アイコンはにゃんどくと同じ線画（もどす＝戻る矢印、やりなおし＝回転矢印、
ヒント＝電球）を `src/ui/icons.ts` に持ってくる。

### クリア演出

現状の `.message-card`（星 3 つ + 手数 + ボタン 3 つ）の構成は維持し、
にゃんどくの `.banner` の実測値に寄せる。

| | 現状 | 新 |
|---|---|---|
| 背景 | `color-mix(in srgb, var(--bg) 78%, transparent)` | `rgb(246 239 228 / .66)` |
| ぼかし | `blur(3px)` | 同じ |
| カードの角丸 | 22px | 22px（同じ） |
| カードの余白 | `28px 24px` | `28px 34px 30px` |
| カードの影 | `0 8px 24px rgb(0 0 0 / .18)` | `0 18px 50px rgb(115 80 86 / .16)` |

カードの一番上に **`happy` 表情の猫を 84px** で置く（にゃんどくの `.banner-cat` と同じ）。
星のポップは現状の実装（`cubic-bezier(.2, 1.4, .4, 1)`、160ms ずつ遅延）を維持する。
